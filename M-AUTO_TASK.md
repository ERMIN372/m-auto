# Задача: лендинг M-AUTO

Ты делаешь одностраничный лендинг для M-AUTO: подбор, проверка, выкуп и доставка автомобилей из Германии и Европы по всей России. У сайта одна цель: получать заявки на подбор.

Ниже мои технические требования. В конце файла дословное ТЗ заказчика (Приложение A) и комментарии посредника (Приложение B).

**Приоритет при конфликте:** ТЗ заказчика > этот файл > твои привычные решения. Если моё требование противоречит ТЗ, делай по ТЗ и напиши мне об этом.

**Сроки:** превью для согласования к четвергу 29.10.2026, финальная версия до конца пятницы 30.10.2026.

---

## 0. Порядок работы

1. Прочитай файл целиком, включая оба приложения.
2. **План, без кода.** Покажи одним сообщением:
   - дизайн-токены: 4–6 цветов в hex с ролями, шрифт и шкала размеров, сетка и отступы, скругления;
   - ASCII-вайрфреймы первого экрана и формы для ширины 390px и 1440px;
   - 3–4 принципа: чем этот лендинг отличается от шаблонного автосайта;
   - структура файлов, решения по форме, отправке заявок и сборке;
   - сверка с ТЗ: пройди по каждому пункту «не делать / не использовать» из ТЗ и по разделу «Антишаблон» ниже. Что в плане выглядит как дефолт, который ты сделал бы для любого похожего сайта, переделай и напиши, что поменял и почему.
   Дальше жди моего «ок».
3. После «ок» создай `CLAUDE.md`: коротко стек, команды сборки и проверки, структура, ключевые правила и запреты из этого файла, где лежит ТЗ. Плюс `.gitignore` и `git init`, если репозитория ещё нет.
4. Работай этапами, после каждого коммит с понятным сообщением:
   - а) каркас, `site.config.json`, сборка;
   - б) первый экран, форма, липкая кнопка на мобиле;
   - в) блоки 3–9;
   - г) блоки 10–12, страницы политики и согласия, `spasibo/`, `404.html`;
   - д) обработчик заявок `api/send.php`;
   - е) SEO, Метрика, фавиконки, `robots.txt`, `sitemap.xml`;
   - ж) QA по чек-листу из раздела 13.
5. После этапов б, в и г снимай скриншоты (раздел 13), сам их смотри и правь, прежде чем идти дальше. Перед каждой сдачей этапа «посмотри в зеркало и сними один аксессуар»: убери лишний элемент, если он не работает на заявку.
6. В конце финальный отчёт (раздел 14).

Не задавай вопросов по контенту. Всё, чего нет в ТЗ, делай аккуратным плейсхолдером и вноси в `CONTENT_TO_REPLACE.md`. Спрашивай, только если без ответа реально нельзя двигаться.

## 1. Контекст

- Заказ пришёл через посредника, он делает лидогенерацию. Реальные фото, кейсы, отзывы и контакты заказчик пришлёт после согласования превью, поэтому всё должно меняться быстро и в одном месте.
- Заявки должны приходить в Telegram-бота (так было у прошлого подрядчика).
- «Сайт должен пройти на Яндексе». Готовим под оба смысла: нормальная индексация в Яндексе и прохождение модерации Яндекс Директа как рекламной посадочной.
- Аудитория: Россия, большинство приходит со смартфона из рекламы.

## 2. Стек и жёсткие ограничения

- Чистые HTML + CSS + vanilla JS. Без фреймворков, без Tailwind и Bootstrap, без jQuery, без npm-зависимостей в рантайме.
- Ни одного внешнего запроса из браузера. Шрифты, иконки и скрипты лежат локально. Никаких Google Fonts, Google Analytics, внешних CDN. Единственное исключение: Яндекс Метрика в prod-сборке, если задан ID. Причины: скорость, доступность из РФ, меньше вопросов по 152-ФЗ.
- Весь контент в HTML. Не рендерить блоки через JS: Яндекс должен видеть страницу без выполнения скриптов.
- **Все пути относительные** (`assets/...`, `privacy/`, `api/send.php`), без ведущего `/`. Превью будет жить в подпапке GitHub Pages (`user.github.io/repo/`), прод в корне домена. Должно работать в обоих случаях.
- Сборка: `scripts/build.py`, Python 3, только стандартная библиотека. Картинки: `scripts/optimize_images.py` на Pillow.
- Обработчик заявок: PHP 8, `api/send.php`. Это стандарт для российских хостингов вроде Beget или Timeweb.
- Браузеры: iOS Safari 15+, Chrome на Android, Яндекс Браузер, свежие десктопные Chrome, Safari, Firefox.

```json
  "prod": {

    "metrika_id": "", "yandex_verification": "",
    "policy_date": ""
  }

```

`scripts/build.py`:

- Подставляет `{{ключ}}` из конфига во все файлы `src/`.
- Генерирует варианты годов для селектов: от текущего года вниз на 20 лет.
- Добавляет к `styles.css` и `main.js` версию по хэшу содержимого (`?v=abc123`), чтобы не мешал кэш.
- `python scripts/build.py --env preview` → `docs/`:
  - `<meta name="robots" content="noindex, nofollow">` и `robots.txt` с `Disallow: /`;
  - маленькая аккуратная плашка «Демо-версия для согласования» в углу, не перекрывает контент;
  - форма в демо-режиме: ничего не отправляет, через ~700 мс показывает успех, payload пишет в консоль;
  - без Метрики, без папки `api/`.
- `python scripts/build.py --env prod` → `dist/`:
  - индексация разрешена, canonical, Open Graph, `sitemap.xml` и `robots.txt` с `site_url`;
  - Метрика, если задан `metrika_id`;
  - форма шлёт на `api/send.php`, папка `api/` копируется без `config.php`.
  - **Падает с понятной ошибкой**, если остались незаполненные ключи или плейсхолдеры (`{{`, `0000000000`, `XX дней`, `X XXX XXX` и пометки `data-placeholder`). Флаг `--allow-placeholders` разрешает собрать для теста.

## 5. Дизайн

Всё, что зафиксировано в разделе «Визуальный стиль» ТЗ, выполняй буквально: светлый, белый, светло-серый, графит, чёрный текст, один спокойный акцент только для CTA, много воздуха, крупная типографика, большие фото, небольшие скругления, Mobile First.

**Тон:** спокойный и дорогой, ощущение реального автомобильного бизнеса с опытом. Не тюнинг, не дешёвый автосалон, не инфобиз.

**Акцент:** один цвет для CTA. Предложение с привязкой к теме: синий немецких указателей автобана, в духе RAL 5017, например около `#0E518D`. Проверь контраст белого текста на нём по AA. Если в плане предложишь другой, обоснуй.

**Шрифт:** одна гарнитура с хорошей кириллицей, не Inter, Roboto, Montserrat и Open Sans по умолчанию. Предложения: Onest или Golos Text (обе под OFL). Скачай файлы, например из репозитория github.com/google/fonts или пакета @fontsource, сделай подмножество latin + cyrillic в woff2 (можно `pyftsubset` из fonttools), `font-display: swap`, preload основного начертания. Лицензию запиши в `CREDITS.md`. Если скачать не выйдет, системный стек.

**Типографика:** шкала через `clamp()`. Ориентиры: H1 на 390px около 32–36px, на десктопе около 56–64px, основной текст 17–18px, строка не длиннее ~70 символов.

**Одна смелая точка.** Блок 7 «Цена фиксируется в договоре» по ТЗ должен быть одним из самых заметных. Сделай его главным визуальным моментом страницы, например инверсия на графитовом фоне с крупной фразой. Всё остальное тихое и дисциплинированное.

**Предметность.** Блок 6 «Проверяем автомобиль до покупки» можно оформить как лист осмотра или отчёт диагностики: строки с отметками. Это работает на доверие и не выглядит шаблоном.

**Антишаблон, не делать:**
- капсовые подписи-«глазки» над заголовками;
- выделение одного слова в заголовке другим цветом или курсивом;
- мета-строки через «·» и подписи вида «СЛОВО — фрагмент»;
- стрелку «→» в тексте кнопок;
- одинаковые карточки с одинаковой серой тенью на всём; одно скругление на всё подряд;
- градиентные подложки, стеклянные эффекты;
- fade-up анимации на каждой секции, параллакс;
- слайдеры и карусели с автопрокруткой, поп-апы при входе, чат-виджеты, таймеры;
- эмодзи вместо иконок.

**Движение:** только как отклик на действия (фокус, отправка формы, смена состояния). Уважай `prefers-reduced-motion`.

**Процесс:** токены → вайрфреймы → сверка с ТЗ → код → скриншоты → правки. Следи за специфичностью CSS: стили секций и кнопок не должны перебивать друг друга. Дизайн-токены в CSS-переменных, чтобы акцент и шрифт менялись в одном месте.

## 6. Тексты и типографика

- Все тексты из ТЗ используй **дословно**. Кавычки «» в ТЗ обозначают границы текста: вокруг заголовков и кнопок их на сайте не ставить.
- Не придумывай факты, цифры, машины, цены, сроки, имена, отзывы, награды. Только то, что есть в ТЗ, остальное плейсхолдеры.
- Новые микротексты (подписи полей, подсказки, ошибки) пиши коротко и просто, от лица интерфейса. Ошибка говорит, что не так и как исправить.
- Типографика: неразрывные пробелы в числах (1 200, 4 850 000 ₽), между числом и ₽, км, дней; после коротких предлогов и союзов; перед тире. Диапазоны через короткое тире (15–25). На сайте кавычки-ёлочки.

## 7. Блоки: детали реализации

**Шапка.** Логотип M-AUTO текстом, легко заменить на SVG. Справа телефон ссылкой `tel:`, только если он задан. Кнопок в шапке нет. Шапка не липкая.

**1. Первый экран.** H1 = главный заголовок. Порядок: H1 → подзаголовок → «Более 1 200 автомобилей…» → кнопка «Получить варианты» → мелко срок доставки → ненавязчиво «Цена фиксируется в договоре». Второй кнопки рядом нет. Фото на десктопе справа или крупно на фоне с читаемым текстом, выбери и обоснуй в плане. **На 390×844 кнопка видна без прокрутки.** Кнопка плавно прокручивает к форме и ставит фокус в поле «Имя».

**2. Форма.** Сразу после первого экрана, подробности в разделе 8.

**3. Доверие.** 4 показателя из ТЗ: на десктопе в одну строку, на мобиле 2×2. Компактно, без больших карточек.

**4. Акция.** Спокойно выделенный блок (фон или рамка), без таймеров, мигания, красного и искусственного дефицита. Кнопка «Получить варианты». Показ по флагу `promo_enabled`.

**5. Авто, которые уже привезли.** 6 карточек: фото, марка и модель, год, срок доставки, цена «под ключ». Страну покупки не указывать. Данные пока заглушки по классам, без реальных марок и цен, чтобы читались разные ценовые категории: «Компактный хэтчбек», «Семейный кроссовер», «Бизнес-седан», «Универсал», «Премиальный внедорожник», «Электромобиль»; год «20XX», срок «XX дней», цена «X XXX XXX ₽ под ключ». У каждой карточки атрибут `data-placeholder` и HTML-комментарий, где менять. Сетка: 1 колонка на мобиле (карточки компактные), 2 на планшете, 3 на десктопе. Без слайдера.

**6. Проверка.** Короткий текст, 7 пунктов проверки, дополнительный текст, кнопка. Тексты дословно.

**7. Фиксированная цена.** Главный визуальный акцент страницы (см. раздел 5). Крупный текст, выделенная фраза про «спокойно ждёте автомобиль». Без юридического текста.

**8. Поэтапная оплата.** 3 шага с номерами 01, 02, 03 (это реальная последовательность, нумерация уместна) и примечание про оплату в рублях и валюте. Подчеркнуть низкий порог входа: 25% на старте.

**9. Ответственность за проверку.** Небольшой блок, тексты дословно. Никаких абсолютных гарантий сверх ТЗ.

**10. Отзывы.** 2–3 слота под фото клиентов с машинами и 3 слота под текстовые отзывы. Заглушки аккуратные, не «лорем»: «Фото клиента с автомобилем», «Здесь будет отзыв клиента: 2–4 предложения о подборе, проверке и получении машины», «Имя, город». Не выдумывать имена и истории. Никакой разметки Review или AggregateRating.

**11. Финальный CTA.** Большой спокойный блок. Кнопка прокручивает к форме и ставит фокус в «Имя». Модалку не делаем: одна форма проще для аналитики и без дублей. Напиши это в отчёте.

**12. Футер.** M-AUTO, подпись из ТЗ, телефон, WhatsApp, Telegram из конфига, ссылки на политику и согласие, блок «Юридическая информация» (наименование, ИНН, ОГРН из конфига), дисклеймер из ТЗ дословно, ©.

**Липкая кнопка на мобиле (до 768px).** «Получить варианты» внизу экрана, заметная. Появляется, когда первый экран ушёл из вида. Прячется, когда форма в зоне видимости, и навсегда после успешной отправки. Учитывает `env(safe-area-inset-bottom)`. Не перекрывает контент: пока она видна, у страницы есть нижний отступ. На десктопе её нет.

Cookie-баннер не делаем: в ТЗ его нет, это лишний шум. Упомяни в отчёте, что с Метрикой заказчик может захотеть его добавить.

## 8. Форма подбора

**Поля строго по ТЗ и в этом порядке.** Год «от» и «до» в одну строку, пробег «от» и «до» в одну строку, даже на 360px.

| Поле | Реализация |
|---|---|
| Имя | `text`, `autocomplete="given-name"`, обязательное, 2–60 символов |
| Марка и модель | `text`, обязательное, 2–80 символов, плейсхолдер «например, Volkswagen Tiguan» |
| Год выпуска от / до | `<select>`, обязательные, годы генерирует сборка; «до» не раньше «от» |
| Пробег от / до | необязательные, `inputmode="numeric"`, пробелы между разрядами при вводе, суффикс «км»; «до» не меньше «от» |
| Telegram или WhatsApp для связи | `text`, обязательное. Принимает телефон или Telegram: `@username`, `username`, ссылку `t.me/...`. Плейсхолдер «+7 999 123-45-67 или @username» |
| Как удобнее связаться? | два крупных переключателя: «Написать в мессенджер» (выбран и визуально выделен по умолчанию) и «Позвонить». При «Позвонить» подпись контакта меняется на «Телефон для звонка», и нужен именно телефон |

**Не спрашивать:** бюджет, город, email, комментарий, комплектацию, способ оплаты.

**Кнопка** «Получить варианты», на мобиле на всю ширину.

**Согласие под кнопкой.** `consent_mode: "checkbox"` по умолчанию: галочка, не отмечена, текст «Согласен на обработку персональных данных» со ссылкой на `consent/`, рядом ссылка на `privacy/`. Без галочки отправить нельзя, ошибка рядом. Режим `"text"`: только строка «Нажимая кнопку, вы соглашаетесь…» со ссылками. Галочка добавлена из-за требований 152-ФЗ к отдельному согласию, в отчёте отметь это как отклонение от ТЗ.

**Удобство одним пальцем:** у всех полей `font-size` не меньше 16px (иначе iOS зумит), зоны нажатия от 48px, правильные `inputmode`, `autocomplete`, `enterkeyhint`, видимый фокус.

**Валидация:** на blur и на отправку, текст ошибки под полем, конкретный («Год до не может быть раньше года от»). При отправке фокус на первое поле с ошибкой. `aria-invalid` и `aria-describedby`. Статус формы в `aria-live`.

**Скрытые поля:**
- `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `yclid`, `referrer`, `landing_url`. Первое касание сохраняй в localStorage на 30 дней (в try/catch), при отправке подставляй;
- `form_ts`: время загрузки страницы;
- ловушка для ботов: поле `company_site`, визуально скрыто (не `display:none`), `tabindex="-1"`, `autocomplete="off"`, `aria-hidden="true"`.

**Состояния:**
1. обычное;
2. отправка: кнопка заблокирована, текст «Отправляем…», повторная отправка невозможна;
3. успех: форма заменяется панелью с текстом «Спасибо! Заявка получена. Менеджер M-AUTO свяжется с вами.» и вторичной кнопкой «Смотреть актуальные авто в Telegram». Эта кнопка есть только после успеха и только если задан `telegram_catalog_url`. До заявки Telegram-каталог нигде как CTA не показывается;
4. ошибка: «Не получилось отправить заявку. Попробуйте ещё раз или свяжитесь с нами:» и контакты из конфига. Введённые данные не теряются.

**Без JS** форма уходит обычным POST на `api/send.php`, после чего редирект на `spasibo/`.

**Превью:** демо-режим, см. раздел 4.

## 9. Обработчик заявок `api/send.php`

**Порядок:** валидация → **сначала запись заявки в файл на хостинге** → отправка в Telegram → по желанию дубль на почту → ответ.

Запись на хостинг первой: это бэкап, если Telegram недоступен, и осторожный вариант по 152-ФЗ (первичный сбор данных на сервере в РФ, если хостинг российский).

**Конфиг** `api/config.php` (в git только `config.example.php`):

```php
<?php
return [
  'bot_token'     => '',            // токен от @BotFather
  'chat_ids'      => [''],          // один или несколько чатов
  'lead_email'    => '',            // необязательно: дубль заявок на почту
  'storage_dir'   => __DIR__ . '/storage', // лучше вне web-root, если хостинг позволяет
  'site_host'     => 'example.ru',  // для мягкой проверки Origin/Referer
  'rate_limit'    => ['max' => 5, 'window_sec' => 600],
  'min_fill_sec'  => 3,
];
```

**Требования:**
- PHP 8, `declare(strict_types=1)`, только POST, без CORS (тот же origin).
- Принимает JSON (fetch) и обычный form POST (без JS → редирект 303 на `../spasibo/`).
- Повторная серверная валидация всех полей по тем же правилам, что на фронте. Длины ограничены, лишние поля игнорируются.
- Антиспам: заполненная ловушка или отправка быстрее `min_fill_sec` → тихо отвечаем «ок» и ничего не шлём. Ограничение частоты по хэшу IP (файлы в storage, `flock`). Сам IP в заявках не хранить.
- Нормализация телефона: 8XXXXXXXXXX и 7XXXXXXXXXX → +7XXXXXXXXXX, 10 цифр на 9 → +7. Telegram: из ссылки или `@` достать username.
- Номер заявки: счётчик в storage с `flock`.
- Хранение: `storage/leads-YYYY-MM.csv`, UTF-8 с BOM, разделитель `;`, чтобы нормально открывался в русском Excel. Колонки: id, дата и время МСК, имя, авто, год от, год до, пробег от, пробег до, контакт, способ связи, utm-метки, yclid, страница, referrer.
- `storage/.htaccess`: `Require all denied` (и вариант для старого Apache). В README предупреждение: на nginx-хостинге .htaccess не работает, тогда `storage_dir` вынести за пределы web-root.
- Telegram: `sendMessage`, `parse_mode=HTML`, весь пользовательский ввод экранировать через `htmlspecialchars`. cURL с таймаутом 5 секунд, фолбэк на `file_get_contents` со stream context, если cURL нет. Несколько `chat_ids` = отправка в каждый.
- Если Telegram не ответил, но заявка записана: ошибка в `storage/errors.log`, дубль на почту (если задан), пользователю всё равно успех. Если не удалось и записать, и отправить: 500 и `{"ok":false}`.
- Ответы: `200 {"ok":true,"id":1043}`, `422 {"ok":false,"errors":{"поле":"текст"}}`, `429`, `500`.

**Шаблон сообщения в Telegram:**

```
🚗 Заявка #1043 · M-AUTO
Имя: Алексей
Авто: Volkswagen Tiguan
Год: 2019–2022
Пробег: до 80 000 км        (или «не указан»)

```

Можно визуально выделить фразу:

«Зафиксировали цену — дальше вы спокойно ждёте автомобиль.»

Не перегружать этот блок юридическим текстом.

8. ПОЭТАПНАЯ ОПЛАТА

«Не нужно оплачивать всё сразу»

Показать 3 простых этапа.

01

«25% аванс»

После выбора автомобиля и заключения договора.

02

«Логистика и оформление»

Оплата производится по согласованному графику.

03

«Финальный расчёт»

После получения автомобиля и постановки на учёт.

Добавить:

«Возможна оплата в рублях и валюте — доступный способ согласовывается индивидуально.»

Блок должен подчёркивать низкий первоначальный порог входа и безопасность сделки.

9. ОТВЕТСТВЕННОСТЬ ЗА ПРОВЕРКУ

Небольшой эмоциональный блок.

Заголовок:

Дополнительный текст:

«Наша задача — не просто привезти автомобиль, а сделать так, чтобы после получения клиента не ждали неприятные сюрпризы.»

Не использовать чрезмерные юридические обещания и абсолютные гарантии, которые не закреплены договором.

⸻

10. ОТЗЫВЫ КЛИЕНТОВ

Заголовок:

«Что говорят клиенты M-AUTO»

Использовать:

2–3 реальные фотографии клиентов рядом с полученными автомобилями;

несколько коротких текстовых отзывов.

Отзывы должны выглядеть естественно.

Не использовать шаблонные фразы вроде:

«Лучшая компания!!! Всем рекомендую!!!»

Лучше формат:

«Изначально рассматривал несколько вариантов. Ребята нашли автомобиль, сделали видеоосмотр и диагностику. Цена была зафиксирована заранее, после получения ничего доплачивать не пришлось.»

Не придумывать имена, фотографии или конкретные истории от лица несуществующих клиентов.

Пока оставить аккуратные placeholder-блоки для последующей замены реальными материалами.

UX И КОНВЕРСИЯ

Главная цель сайта:

получение заявки.

Основной CTA на всём сайте:

«Получить варианты»

Использовать эту кнопку несколько раз, но не после каждого блока.

Не использовать слово:

«Оставить заявку»

как основной CTA.

Не требовать от посетителя слишком много информации.

Не спрашивать бюджет в первой форме.

Не уводить посетителя в Telegram до получения заявки.

После отправки формы можно предложить перейти в Telegram-каталог.

На мобильной версии можно использовать компактную фиксированную кнопку в нижней части экрана:

«Получить варианты»

Все формы должны быть удобны для заполнения одним пальцем со смартфона.

SEO

Основная тематика:

авто из Европы;

авто из Германии;

пригнать автомобиль из Европы;

подбор автомобиля в Европе;

доставка авто из Европы в Россию.

Не превращать главный экран в SEO-текст.

SEO использовать естественно в:
title;
description;
H1;
H2;
alt изображений;
небольших текстах страницы.

«Авто из Германии и Европы под заказ | M-AUTO»

«M-AUTO — подбор, проверка и доставка автомобилей из Германии и Европы по всей России. Фиксированная цена по договору, полная проверка авто и доставка автовозами.»

ОСНОВНОЙ ПРИНЦИП

Человек за первые 10–15 секунд должен понять:

что M-AUTO привозит автомобили из Европы;

что автомобиль тщательно проверяют;

что цена фиксируется;

что компания работает 9 лет;

что привезено более 1 200 автомобилей;

что доставка занимает в среднем 15–25 дней после выкупа;

что не нужно сразу оплачивать всю сумму;

что можно быстро оставить короткую заявку и получить варианты.

Главный сценарий:

Зашёл на сайт → понял предложение → увидел доверительные факторы → нажал «Получить варианты» → заполнил короткую форму → передал контакт → менеджер продолжил продажу лично в Telegram / WhatsApp / по телефону.
