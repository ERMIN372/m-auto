# M-AUTO: лендинг подбора авто из Германии и Европы

Одностраничный сайт с одной целью: заявка на подбор. Чистые HTML, CSS и JS, сборка на Python, приём заявок на PHP 8 с отправкой в Telegram-бота.

- ТЗ и технические требования: [`M-AUTO_TASK.md`](M-AUTO_TASK.md)
- Что заменить перед запуском: [`CONTENT_TO_REPLACE.md`](CONTENT_TO_REPLACE.md)
- Лицензии шрифта и картинок: [`CREDITS.md`](CREDITS.md)

## Быстрый старт

Нужно: Python 3.9+. Для картинок ещё Pillow (`pip install Pillow`), для проверки обработчика PHP 8.0+.

```bash
python3 scripts/build.py --env preview      # превью → docs/
python3 -m http.server 8000 -d docs         # открыть http://localhost:8000
```

| Команда | Что делает |
|---|---|
| `python3 scripts/build.py --env preview` | превью в `docs/`: `noindex`, `robots.txt` с `Disallow: /`, плашка «Демо-версия», форма ничего не отправляет |
| `python3 scripts/build.py --env prod` | боевая сборка в `dist/`. **Падает**, если в конфиге пустые обязательные ключи или на сайте остались заглушки |
| `python3 scripts/build.py --env prod --allow-placeholders` | prod-сборка для теста, заглушки разрешены |
| `python3 scripts/optimize_images.py` | фото из `src/assets/img/raw/` → WebP и JPEG 480–1600 px (для первого экрана ещё 1920) |
| `python3 scripts/optimize_images.py --icons` | `favicon.ico`, `apple-touch-icon.png`, `og-image.jpg` (из `raw/og.jpg` или типографская заглушка) |

## Как устроено

```
site.config.json     все меняющиеся данные: контакты, юр. лицо, ссылки, ID Метрики
src/                 исходники сайта
  _partials/         шапка, футер, общие теги <head> (вставляются при сборке)
  index.html         лендинг
  privacy/ consent/  политика и согласие (шаблоны, нужна проверка юристом)
  spasibo/ 404.html  страница после отправки без JS и 404
  api/send.php       приём заявок
  assets/            css, js, шрифт, картинки
scripts/             сборка, картинки, QA
docs/                собранное превью для GitHub Pages (генерируется, коммитится)
dist/                собранный прод (генерируется, в git не попадает)
```

В исходниках есть служебные пометки, которые понимает `build.py`:

- `{{phone_display}}` подставляет значение из `site.config.json`;
- `<!-- if:whatsapp_url -->…<!-- endif:whatsapp_url -->` вырезает блок, если ключ пустой;
- `<!-- img:hero alt="…" … -->` даёт `<picture>`, если фото есть, иначе SVG-заглушку;
- неразрывные пробелы (после предлогов, в числах, перед тире) ставит сборка: в исходниках пишутся обычные пробелы.

## Как менять контент

Всё, что нужно заменить, со способом и размерами, перечислено в [`CONTENT_TO_REPLACE.md`](CONTENT_TO_REPLACE.md). Коротко:

1. Контакты и юр. данные: секция `prod` в `site.config.json`.
2. Фото: положить в `src/assets/img/raw/` с нужным именем → `optimize_images.py` → `build.py`.
3. Кейсы и отзывы: прямо в `src/index.html`, блоки помечены комментариями `КЕЙС 1`, `ОТЗЫВ 1` и т.д.
4. Пересобрать: `python3 scripts/build.py --env preview` и `--env prod`.

## Превью на GitHub Pages

1. Собрать превью и закоммитить `docs/`.
2. Settings → Pages → Build and deployment → **Deploy from a branch** → ветка `main`, папка `/docs` → Save.
3. Через 1–2 минуты превью откроется по адресу вида `https://<user>.github.io/<repo>/`.

Пока ветка не слита в `main`, можно временно выбрать в настройках рабочую ветку. Превью закрыто от индексации (`noindex` и `Disallow: /`), форма работает в демо-режиме: через 0,7 с показывает успех и пишет данные в консоль браузера. Если репозиторий переименуют, поправьте `preview.site_url`: от него зависят только ссылки в тексте документов.

## Запуск на хостинге (Beget, Timeweb и другие с PHP 8)

1. **Заполнить контент.** Секция `prod` в `site.config.json` и все пункты из `CONTENT_TO_REPLACE.md`.
2. **Собрать:** `python3 scripts/build.py --env prod`. Если что-то не заполнено, сборка остановится и напишет, что именно.
3. **Залить** содержимое папки `dist/` в корень сайта (обычно `public_html/`) через файловый менеджер панели или SFTP. Проверьте, что скрытые файлы `.htaccess` тоже загрузились.
4. **Настроить обработчик.** В `api/` скопировать `config.example.php` в `config.php` и заполнить:
   - `bot_token` и `chat_ids` (см. раздел про бота ниже);
   - `site_host`: домен сайта без `https://`, для кириллического домена в punycode (`xn--...`);
   - `lead_email`, если нужен дубль заявок на почту (хостинг должен уметь отправлять почту через `mail()`);
   - `storage_dir`: папка для заявок. По умолчанию `api/storage` внутри сайта. Если хостинг позволяет, лучше вынести её выше `public_html`, например `'storage_dir' => dirname(__DIR__, 2) . '/m-auto-storage'`.
5. **Права.** Папка `storage` должна быть доступна PHP на запись: обычно `755` на папку и `644` на файлы. Если заявки не пишутся, попробуйте `775`.
6. **Проверить закрытость.** Откройте в браузере `https://домен/api/storage/` и `https://домен/api/config.php`: в ответ должна прийти ошибка 403. Если файлы открываются, хостинг работает на nginx без `.htaccess`. Тогда **обязательно вынесите `storage_dir` за пределы сайта** (п. 4), иначе заявки окажутся в открытом доступе.
7. **HTTPS.** Включите бесплатный SSL (Let's Encrypt) в панели хостинга. Убедитесь, что сайт открывается по `https://`, и раскомментируйте в корневом `.htaccess` блок с редиректом на https. Там же выберите основной адрес: с `www` или без (замените `example.ru` на свой домен). Строку `Strict-Transport-Security` включайте последней, когда всё работает.
8. **Тестовая заявка.** Отправьте форму с телефона. Проверьте, что сообщение пришло в Telegram, в `storage/leads-ГГГГ-ММ.csv` появилась строка, а в `storage/errors.log` нет новых ошибок.

Что важно знать про обработчик:

- Заявка сначала пишется в CSV на хостинге, потом уходит в Telegram. Если Telegram не ответил, посетитель всё равно видит успех, заявка лежит в CSV, а ошибка пишется в `errors.log`.
- CSV в UTF-8 с BOM и разделителем `;`: русский Excel открывает его двойным щелчком. Контакт записывается как `тел. +7 999 123-45-67` или `tg @username`.
- IP посетителей не сохраняется: для лимита частоты (по умолчанию 5 заявок за 10 минут) используется хэш с солью.
- В `errors.log` нет персональных данных, только номер заявки и тип ошибки.
- Если хостинг стоит за прокси и у всех посетителей одинаковый `REMOTE_ADDR`, лимит сработает на всех сразу. Тогда увеличьте `rate_limit.max` или уточните у хостинга, как получить реальный IP.

## Telegram-бот

1. Написать [@BotFather](https://t.me/BotFather) → `/newbot` → имя и username бота. Он пришлёт токен вида `123456:ABC...`, это `bot_token`.
2. Добавить бота в рабочий чат (группу менеджеров). Если заявки нужны в личку, просто начните диалог с ботом.
3. Отправить в чат любое сообщение или `/start`.
4. Открыть в браузере `https://api.telegram.org/bot<TOKEN>/getUpdates` (вместо `<TOKEN>` токен целиком) и найти `"chat":{"id": ...}`. У групп id отрицательный, у супергрупп начинается с `-100`.
5. Вписать id в `chat_ids`. Можно несколько: `['-1001234567890', '123456789']`, заявка уйдёт в каждый.

Если `getUpdates` пустой, напишите в чат ещё раз. Если бот в группе не видит сообщений, в @BotFather → Bot Settings → Group Privacy выключите режим приватности, повторите шаги 3–4 и включите обратно.

## Яндекс Вебмастер и Метрика

**Вебмастер** ([webmaster.yandex.ru](https://webmaster.yandex.ru)):

1. Добавить сайт с `https://`.
2. Подтвердить права способом «Мета-тег»: значение `content` вписать в `prod.yandex_verification`, пересобрать и залить сайт.
3. Индексирование → Файлы Sitemap: добавить `https://домен/sitemap.xml`.
4. Проверить `robots.txt` в разделе «Инструменты». В нём закрыты `/api/` и `/spasibo/`, а `Clean-param` склеивает адреса с UTM-метками.

**Метрика** ([metrika.yandex.ru](https://metrika.yandex.ru)):

1. Создать счётчик и вписать его номер в `prod.metrika_id`. Вебвизор включается флагом `shared.metrika_webvisor`. Пересобрать сайт.
2. Цели → Добавить цель → тип «JavaScript-событие» и идентификатор:

| Идентификатор | Когда срабатывает |
|---|---|
| `lead_success` | заявка успешно отправлена. **Главная цель для Директа** |
| `cta_click` | нажата любая кнопка «Получить варианты», параметр `where`: hero, promo, inspection, final, sticky, form |
| `form_start` | посетитель начал заполнять форму (сам поставил курсор в поле или начал вводить) |
| `tg_catalog_click` | переход в Telegram-каталог после заявки |
| `phone_click` | нажатие на телефон, параметр `where` |
| `messenger_click` | нажатие на WhatsApp или Telegram в футере |

3. Для отправки без JS (редкий случай) можно добавить цель «Посещение страниц» с условием «URL содержит `/spasibo/`».

## Перед запуском рекламы в Директе

- [ ] Форма отправляет заявку, она приходит в Telegram (тестовая заявка с телефона).
- [ ] В футере реальные телефон, мессенджеры и юр. данные: наименование, ИНН, ОГРН, адрес.
- [ ] Политика и согласие открываются, в них реальные реквизиты и дата, тексты проверил юрист.
- [ ] Сайт открывается по HTTPS, http редиректит на https.
- [ ] Акция «Подбор бесплатно до конца месяца» действительно действует, иначе `promo_enabled: false`.
- [ ] Кейсы и отзывы реальные, клиенты согласны на публикацию.
- [ ] Метрика стоит, цель `lead_success` создана и привязана к кампании.

## Проверка (QA)

```bash
python3 scripts/build.py --env preview && python3 -m http.server 8000 -d docs &
node scripts/qa/screens.js http://localhost:8000/ qa     # скриншоты 360/390/768/1440 + проверки
node scripts/qa/form.js http://localhost:8000/           # форма, CTA, липкая кнопка, цели
python3 scripts/build.py --env prod --allow-placeholders
python3 scripts/qa/test_api.py                           # send.php с заглушкой Telegram
bash scripts/qa/e2e_prod.sh                              # prod-форма → send.php, с JS и без
```

Скрипты на Node используют Playwright с Chromium. Встроенный сервер PHP не читает `.htaccess`, поэтому закрытость `storage` проверяется уже на хостинге (п. 6 выше).
